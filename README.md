# ระบบ POS ร้านอาหาร

Webapp ขายหน้าร้าน ใช้บน iPad / มือถือ / คอมพิวเตอร์ ผ่านเว็บเบราว์เซอร์

- **หน้าเว็บ**: ไฟล์ static ในโฟลเดอร์ `public/` เผยแพร่ด้วย **GitHub Pages** (ไม่ต้องมีเซิร์ฟเวอร์)
- **ฐานข้อมูล + ล็อกอิน**: **Supabase** (Postgres + Auth) — ความปลอดภัยทั้งหมดอยู่ในฐานข้อมูล
- **จัดการบัญชีผู้ใช้**: Supabase Edge Function `admin-users`

```
iPad (Safari)  ──HTTPS──>  GitHub Pages (public/)        หน้าเว็บ
      │
      └──────HTTPS──────>  Supabase
                             ├─ Auth                     ล็อกอิน
                             ├─ Postgres + RLS            ข้อมูล + สิทธิ์
                             │   └─ checkout(), sales_summary(), void_order()
                             └─ Edge Function admin-users เพิ่ม/ลบ/รีเซ็ตรหัสผู้ใช้
```

## ใช้งาน

เปิด https://pachara0pin.github.io/pos/ บน iPad → Safari → แชร์ → **เพิ่มไปยังหน้าจอโฮม** จะได้ไอคอน POS เปิดเต็มจอเหมือนแอป

ไม่ต้องเปิดคอมพิวเตอร์ทิ้งไว้ ใช้ได้ทุกที่ที่มีอินเทอร์เน็ต

## ฟีเจอร์

**Staff**
- กดรายการอาหารตามหมวด / ค้นหา, ปรับจำนวน, ใส่หมายเหตุ (เช่น ไม่เผ็ด)
- เลือก ทานที่ร้าน (ใส่เลขโต๊ะ) / กลับบ้าน
- ส่วนลด, คำนวณยอดอัตโนมัติ
- ชำระเงินสด (ปุ่มเงินด่วน + คำนวณเงินทอน) หรือสแกน QR
- พิมพ์ใบเสร็จ, ดูบิลวันนี้
- หลังคิดเงิน ออก **ใบสั่งอาหารแยกตามครัว** อัตโนมัติ (1 ครัว = 1 ใบ, ไม่มีราคา, ตัวใหญ่อ่านง่าย) — ปิดการพิมพ์อัตโนมัติได้ต่อเครื่อง และพิมพ์ซ้ำ/พิมพ์เฉพาะครัวได้จากหน้าบิล

**Admin** (ทำได้ทุกอย่างของ Staff และ)
- เพิ่ม/แก้/ลบเมนู, ปรับราคาในตาราง (พิมพ์แล้วกด Enter), เปิด/ปิดขาย
- เพิ่ม/เปลี่ยนชื่อ/ลบ **ครัว** (ปุ่ม "จัดการครัว" ในหน้าจัดการเมนู) และเลือกครัวของแต่ละเมนู — เมนูที่ไม่ระบุครัวจะออกใบ "ไม่ระบุครัว"
- เพิ่ม/ลบ บัญชีผู้ใช้, รีเซ็ตรหัสผ่าน
- เพิ่ม/ลบ บัญชีรับเงิน QR
  - **เลข PromptPay** → สร้าง QR พร้อมยอดเงินให้ทุกบิล (สร้างในเครื่อง)
  - **อัปโหลดรูป QR** ของร้าน (ลูกค้ากรอกยอดเอง)
- ยกเลิกบิล (ไม่นับในยอดขาย)
- สรุปยอดขาย รายวัน / รายเดือน: ยอดรวม, เงินสด vs QR, ทานที่ร้าน vs กลับบ้าน, เมนูขายดี, รายชั่วโมง/รายวัน

## เครื่องพิมพ์แยกตามครัว

แต่ละครัวเลือกได้ (จัดการเมนู → จัดการครัว → "พิมพ์ใบสั่งที่"):

- **เครื่องคิดเงิน** — พิมพ์ใบสั่งที่ iPad ที่คิดเงิน (ค่าเริ่มต้น)
- **เครื่องประจำครัว** — ส่งใบสั่งไปพิมพ์ที่อุปกรณ์ของครัวนั้นโดยอัตโนมัติ

ตั้งเครื่องประจำครัว:

1. อุปกรณ์ที่ครัว (iPad / แท็บเล็ต Android / คอมเก่า) ต่อเครื่องพิมพ์ใบเสร็จของครัว (AirPrint / USB / Wi-Fi) แล้วตั้งเป็นเครื่องพิมพ์หลัก
2. เปิดเว็บ POS ล็อกอิน (บัญชี staff ก็ได้) → เมนู **จอครัว** → เลือกครัว → **เริ่มรับออเดอร์** → กด **ทดสอบพิมพ์**
3. เปิดหน้านี้ค้างไว้ (ระบบกันหน้าจอดับให้ถ้าเบราว์เซอร์รองรับ)

การทำงาน: คิดเงินเสร็จ → ใบงานเข้าคิวในฐานข้อมูล → เครื่องประจำครัวได้รับทันที (realtime) มีเสียงเตือนและพิมพ์อัตโนมัติ; ถ้า realtime หลุดยังตรวจคิวเองทุก 15 วินาที — งานไม่หาย
- หน้าคิดเงินแสดงสถานะแต่ละครัว (ส่งแล้ว / พิมพ์แล้ว / เครื่องครัวออฟไลน์) และมีปุ่ม **พิมพ์ที่นี่แทน** ถ้าเครื่องครัวไม่รับ (ไม่พิมพ์ซ้ำสองที่)
- ยกเลิกบิล → ครัวได้ **ใบแจ้งยกเลิก** อัตโนมัติ
- มีเครื่องประจำครัว 2 เครื่องในครัวเดียวได้ (ใบหนึ่งพิมพ์ที่เครื่องเดียว)

**พิมพ์โดยไม่ต้องกดยืนยัน**: เบราว์เซอร์ทั่วไปจะเปิดหน้าต่าง "พิมพ์" ทุกครั้ง (บน iPad ต้องแตะ "พิมพ์" เสมอ — ข้อจำกัดของ iOS)
ถ้าต้องการให้ออกทันที ใช้คอมพิวเตอร์ / กล่อง Android ที่ติดตั้ง Chrome แล้วเปิดด้วยคำสั่ง:

```
chrome --kiosk-printing https://pachara0pin.github.io/pos/#/station
```

(Chrome จะพิมพ์ไปที่เครื่องพิมพ์หลักทันทีโดยไม่ถาม)

## ความปลอดภัย

หน้าเว็บเป็นไฟล์สาธารณะ (ใครก็โหลดได้) จึงออกแบบให้ **ฐานข้อมูลเป็นผู้ตัดสินสิทธิ์ทั้งหมด**:

- ทุกตารางเปิด Row Level Security — ผู้ที่ไม่ได้ล็อกอินอ่าน/เขียนอะไรไม่ได้เลย
- Staff อ่านเมนู/บิลได้ แต่แก้เมนู ยกเลิกบิล หรือดูรายงานไม่ได้
- **ยอดเงิน ราคา และเลขบิลคำนวณในฐานข้อมูล** (ฟังก์ชัน `checkout`) — แก้ราคาจากหน้าเว็บไม่ได้
- บิลแก้ตรงๆ ไม่ได้แม้แต่ admin (ยกเลิกได้ผ่าน `void_order` เท่านั้น)
- `public/config.js` มีแค่ URL และ anon (publishable) key ซึ่งเปิดเผยได้ตามการออกแบบของ Supabase
- คีย์ service role อยู่ใน Supabase (Edge Function) และไฟล์ `.env` ในเครื่องเท่านั้น — **ห้าม commit `.env`**

เมื่อเน็ตสะดุด: การอ่านข้อมูลลองใหม่อัตโนมัติ / การคิดเงินมีรหัสคำขอ (request_id) — ลองใหม่กี่ครั้งก็ได้บิลเดียว ไม่เกิดบิลซ้ำ

## ติดตั้งใหม่ (สำหรับผู้ดูแลระบบ)

1. สร้างโปรเจกต์ Supabase (Region: Southeast Asia (Singapore))
2. Authentication → Sign In / Providers → **ปิด "Allow new users to sign up"** (บัญชีสร้างโดย admin เท่านั้น)
3. สร้าง `.env` จาก `.env.example` (ใส่ `DATABASE_URL` แบบ Session pooler)
4. สร้างตาราง/สิทธิ์/ฟังก์ชัน:
   ```bash
   psql "$DATABASE_URL" -f supabase/migrations/001_schema.sql
   ```
5. Deploy Edge Function:
   ```bash
   supabase login
   supabase functions deploy admin-users --project-ref <project-ref>
   ```
6. ใส่ URL และ anon key ของโปรเจกต์ใน `public/config.js`
7. สร้าง admin คนแรก: Supabase Dashboard → Authentication → Add user (อีเมล `admin@pos.local`) แล้วเพิ่มแถวในตาราง `profiles` (`role = admin`)
8. เปิด GitHub Pages: Settings → Pages → Source: **GitHub Actions** (workflow อยู่ที่ `.github/workflows/pages.yml`)

ชื่อผู้ใช้ในหน้าเข้าสู่ระบบ = ส่วนหน้า @ ของอีเมล `<username>@pos.local` (ไม่มีการส่งอีเมลจริง)

## ทดสอบในเครื่อง

```bash
npx serve public
```

## สคริปต์

- `node scripts/db-check.js` — ตรวจความเร็ว/ความเสถียรของการเชื่อมต่อฐานข้อมูล
- `node scripts/migrate-users.js` — ย้ายบัญชีจากเวอร์ชัน Node server เดิมไป Supabase Auth (ใช้ครั้งเดียว)

> แผนฟรีของ Supabase จะหยุดโปรเจกต์ชั่วคราวถ้าไม่มีการใช้งาน 7 วัน (กด Restore ใน Dashboard ได้) และไม่มี backup อัตโนมัติ — ควร export ข้อมูลเป็นระยะ
